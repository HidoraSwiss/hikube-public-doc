## Errors

An error response carries an HTTP status for the class of the error and a JSON body (`ErrorResponse`) whose `code` identifies the precise error:

```json
{"requestId": "4bf92f3577b34da6a3ce929d0e0e4736", "code": 20101, "message": "invalid name: must be at least 3 characters", "details": []}
```

A code reads as a service prefix followed by three digits: `001`–`099` are platform errors (not found, already exists, unavailable…), `100`–`199` invalid input, `200`–`299` business rules. Handle errors on `code`: the wording of `message` may change.

| Code | Error |
|------|-------|
| 10001 | Authentication failed: invalid bearer token |
| 10002 | Permission denied: missing or invalid credentials, or credentials that do not allow this operation |

| 10004 | The api-key could not be checked (temporary); retry, the key is not known to be invalid |
| 10005 | Refused by a platform admission policy; the message names the field, `details` the policy and its reason |
| 10006 | Invalid update_mask: a path names no updatable field, or one key of a collection |
